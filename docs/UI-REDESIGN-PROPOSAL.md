# 旅行穿搭规划助手 — 前端样式与布局改版建议

> 基于当前 Streamlit 实现（`backend/app/`）与用户视角的可用性分析。  
> 配套 HTML 原型见 [`prototypes/`](./prototypes/) 目录。

---

## 一、当前体验的主要问题（用户视角）

| 问题 | 用户感受 | 根因 |
|------|----------|------|
| **视觉单调** | 像「表单 + 报告」，不像旅行/时尚产品 | 默认 Streamlit 白底、红色主按钮，缺少品牌色与层次 |
| **点击层级过深** | 想看完一天穿搭要点要点 5–7 次 | 天气趋势、旅行提醒、单品清单、上/下/鞋/配饰均为 `expander` 折叠 |
| **Tab 割裂信息** | 概要 / AI 图 / 商品三者来回切，难以建立「这套穿搭 → 这张图 → 这些商品」的关联 | 三个 Tab 平级，无「一屏总览」模式 |
| **日期切换无预览** | 只有 `6/5`、`6/6` 文字，不知道哪天冷/雨 | 日期 Tab 未携带天气 icon、温差等摘要 |
| **目的地太粗** | 填「大理」无法表达「洱海骑行 + 古城拍照」 | 仅有 `text_input`，无景点/日程粒度 |
| **AI 图与场景脱节** | 效果图是泛化「旅行场景」，不是用户真正会去的地方 | 生图 prompt 仅映射「拍照→打卡地」等活动标签 |
| **商品区像列表** | 折叠标题长、一列展开、缺少购物欲 | 商品在 expander 内，图片区常为空占位 |

## 二、改版方向总览

### 2.1 视觉与品牌

- **主色**：保留珊瑚红作 CTA（与淘宝导购一致），搭配 **暖沙色背景 `#FAF7F2`** + **深墨文字 `#1C1917`**
- **辅色**：天空蓝（天气）、鼠尾草绿（舒适/自然场景）、淡紫（AI/科技）
- **字体**：标题略加大字重；正文 15–16px；数字/价格用 tabular figures
- **圆角与阴影**：卡片 `16px` 圆角 + 轻阴影，替代 Streamlit 默认直角块
- **Streamlit 落地**：扩展 `styles.css`，用 `st.markdown(unsafe_allow_html=True)` 注入卡片 HTML；`st.set_page_config` 可配合 `theme.primaryColor`

### 2.2 信息架构：减少折叠，增加「扫读」

**建议默认展开的内容：**

- 当日一行天气（已有，保留）
- 旅行提醒（最多 2 条 bullet，其余收进「更多提醒」）
- 推荐理由（info 框改为左侧色条卡片，更醒目）
- 单品清单（改为 **横向 chip 条** 或 **2×2 网格**，不再 expander）
- 商品（改为 **品类 Tab**：上装 | 下装 | 鞋 | 配饰，默认展示 2–3 张商品卡）

**仍可折叠的内容：**

- 全程「行程天气趋势」图表（非每日必看）
- 体型与穿搭偏好（表单侧，保持 expander）

### 2.3 日期导航：从 Tab 升级为「行程时间轴」

每个日期块展示：

```
[ 6/5 周五 ]  🌧 16–27°   📍 洱海
[ 6/6 周六 ]  ☀ 18–28°   📍 大理古城
```

- 选中态：底部色条 + 浅底
- 未选中：灰字 + hover 提示
- **Streamlit**：`st.tabs` 标签可改为自定义 HTML + `st.session_state.selected_day` + 按钮；或 tabs 上方用 `st.columns` 渲染 metric 摘要

### 2.4 目的地 → 景点 → 每日绑定（核心功能增强）

**输入流程建议：**

1. **城市/目的地** — 搜索框（可接 POI API，参考 `helloagents-trip-planner`）
2. **推荐景点** — 城市选定后展示卡片网格（洱海、崇圣寺三塔、古城人民路…）
3. **日程分配** — 将景点拖到各日期，或「智能分配」一键排期
4. **每景点场景标签** — 拍照 / 徒步 / 下午茶（影响穿搭逻辑）

**数据结构扩展（后端）：**

```python
# TripContext 建议新增
daily_spots: list[list[str]]  # 每天去的景点名
spot_photos: dict[str, str]   # 景点参考图 URL（可选）
```

**AI 效果图：**

- 由「每天 1 张 generic 图」→ **「每景点 1 张」** 或 **主景点 1 张 + 缩略图切换**
- Tab「AI 效果图」内增加 **景点 pill 切换**（洱海 | 古城 | 苍山）
- 图片 caption：`AI 生成 · 洱海生态廊道 · 休闲风 · 仅供参考`

### 2.5 概要 / AI 图 / 商品：三种布局策略

| 策略 | 适用 | 说明 |
|------|------|------|
| **A. 杂志单页**（原型 v1） | 想一眼看完 | 左文右图，下方商品横滑；适合演示 |
| **B. 仪表盘卡片**（原型 v2） | 日常主力 | 顶部 KPI + 品类 Tab 商品；折叠最少 |
| **C. 分屏购物**（原型 v3 前半） | 强调导购 | 左穿搭摘要，右商品网格同步高亮 |

当前三 Tab 可保留为 **「视图切换」** 而非 **「内容分割」**：同一数据，三种密度。

### 2.6 未来「AI 换装」布局要点（原型 v3）

```
┌─────────────────────────────────────────────────────────┐
│  [用户照片]     [已选商品条: 上装 下装 鞋 配饰]          │
│       ↓                    ↓                            │
│              [ AI 换装预览 · 可切景点背景 ]              │
│  左侧：上传/选模特  右侧：结果图  底部：商品池可替换      │
└─────────────────────────────────────────────────────────┘
```

- **输入**：用户上传半身/全身照，或选系统模特
- **商品来源**：从「推荐商品」一键「加入试穿」；支持替换同品类
- **背景**：与当日 `daily_spots` 联动，换装结果叠加景点背景
- **Streamlit 预留**：右侧报告区固定 **40% 宽试穿面板**；`st.file_uploader` + `st.session_state.tryon_selection`

## 三、组件级改造对照（Streamlit）

| 区块 | 现状 | 建议 |
|------|------|------|
| 页面标题 | 简单 h1 + 副标题 | 渐变顶栏 + 行程摘要 chip 行 |
| 左侧表单 | 标准 form | 分步：① 目的地+景点 ② 日期+分配 ③ 风格预算 |
| 天气趋势 | expander 折叠 | 默认可折叠；**摘要三指标始终可见**（已有 metric，移到 expander 外） |
| 日期 | `st.tabs` 纯文字 | 自定义 day-pill（HTML）或 tabs + caption 天气 |
| 概要 Tab | 多个 expander | 提醒 + 理由 + 单品网格 **默认展开** |
| AI 图 Tab | 单图 | 景点 sub-tabs + 大图 + 下载/放大 |
| 商品 Tab | 4 个 expander | 品类 segmented control + 2–3 列卡片 |
| 免责声明 | 底部小字 | 固定 footer 样式，降低视觉权重 |

## 五、实施优先级建议

1. **P0 — 视觉/CSS**：`styles.css` 品牌色、卡片、day-pill（1–2 天）
2. **P0 — 减少 expander**：单品改网格、商品改品类 Tab（1 天）
3. **P1 — 日期时间轴**：HTML day-nav + session state（1 天）
4. **P1 — 景点选择 UI**：表单侧 multiselect + 按日分配（需 POI 数据，2–3 天）
5. **P2 — 多景点 AI 图**：后端 `image.md` prompt + 按 spot 生图（3–5 天）
6. **P3 — AI 换装**：独立面板 + 试穿 API（产品化阶段）
